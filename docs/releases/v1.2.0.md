# OmniVec v1.2.0

This release brings together the changes since v1.1.4 and the optimized ingestion
and telemetry work. The known limitations below remain open; this is not a claim
that every integration has passed live production acceptance.

## Included changes

- Nonblocking ingestion and worker metrics: bounded process-local queues, one
  background HTTP sender, bounded retries/timeouts/drain, and explicit loss logs.
- Remove the Cosmos metrics-document updater and readers. Export worker batches
  asynchronously to App Insights, deduplicate across API replicas, apply pipeline
  reset cutoffs, and label historical versus process-local coverage.
- Grant workspace-only Log Analytics Reader to the API workload identity.
- Router binary float32 embedding responses with JSON compatibility and optional
  unpooled connections for model-replica balancing.
- Opt-in direct model routes, bounded batching/concurrency, endpoint rotation,
  base64 float32 decoding, and logged router fallback.
- Cosmos inline float-array reuse, suppressed unused PATCH response bodies,
  configurable PATCH concurrency, RetryAfter handling, and phase/RU diagnostics.
  Required writes still complete before checkpointing.
- Cosmos queue destinations use full upserts with partition-scoped, payload-aware
  batching. Ordinary unchunked records do not issue replacement cleanup queries.
- Configurable Cosmos chunk replacement order: insert-first or delete-first.
  Chunk settings are exposed through the API and modern/classic consoles.
- Native Garnet HASH sources and inline Garnet-to-Garnet processing, with positive
  monotonic document versions, explicit tombstones, checkpoints, version-fenced
  vector writes, source validation/sampling/health checks, and console support.
- First-class Garnet vector destinations and search, deterministic identities,
  metadata, authentication configuration, and version-fenced updates/deletes.
- OneLake Iceberg ingestion, durable checkpoints, recovery scans, cross-tenant
  identities, Fabric Spark write-back, configurable merge batching, and optional
  Garnet serving mirrors.
- OneLake Delta CDF streaming inserts, updates, and deletes, deterministic messages,
  metadata-feedback filtering, and recovery polling.
- SharePoint Graph delta ingestion, stable item identities, pipeline-scoped
  cross-tenant identities, bounded downloads, extraction/chunking, Cosmos
  synchronization manifests, revision fencing, and delete reconciliation.
- Word document ingestion and supported-format extraction, empty-document handling,
  and extraction scratch-file cleanup.
- Connector recovery improvements for Blob watermarks, SQL paging, Databricks
  result chunks, cancellation, retries, and message settlement.
- Durable model registry/routing recovery, credential preservation, concurrent
  registration fencing, and explicit persistence failures.
- Cosmos full-text and hybrid search, composable index modes, and chat-model
  validation.
- Redesigned SPA, guided resource/permission forms, operations/recovery console,
  diagnostics, troubleshooting chat, and approval-controlled recovery.
- Entra login provisioning, role/audience handling, redirect bridge, and logout.
- Resumable azd deployment, image-build tracking, isolated Helm dependency caches,
  updated ingestion build contexts, Cosmos MCP integration, and regression/chaos
  coverage.

## Verified benchmark results

Both cases used GPU BGE Small, approximately 10-token inputs, normal production
writes, and the nonblocking telemetry transport. Rates include source insertion,
processing, and persisted embeddings; they are not model-only throughput.

| Path | Documents | End-to-end time | Persisted documents/s |
|---|---:|---:|---:|
| Cosmos DB -> BGE -> same Cosmos container, inline | 100,000 | 50.135 s | 1,994.6 |
| Native Garnet -> BGE -> Garnet, inline | 100,000 | 95.733 s | 1,044.6 |

The Cosmos case used 96,200 RU/s within a 100,000 RU/s account budget. Garnet was
private, self-hosted, memory-backed, and shared existing GPU-node CPU capacity:
these are not managed Garnet or disk-durability results. Larger-document rates
and the 4,000 persisted documents/s target are not established by these tests.

## Upgrade and deployment notes

- Rebuild the API, ingestion, worker, router, pipeline-worker, and web components
  from this tag, or use matching versioned images after publication completes.
  Publishing the GitHub release does not itself deploy those images to AKS.
- The ingestion Docker build now requires repository-root context because it
  references the worker project.
- Historical telemetry requires App Insights configuration, a workspace ID, and
  workspace-scoped Log Analytics Reader for the API workload identity.
- Telemetry is best-effort and eventually consistent. Buffer overflow, shutdown,
  and exporter outages can lose reports. Verify destination records independently.
  Legacy Cosmos metrics data is preserved but is not read as a fallback.
- Garnet HASH values require an id, positive Int64 version, and string content.
  Changes require increasing versions; deletion requires an explicit versioned
  tombstone. Hard HDEL is not deletion propagation. Native sources support only
  inline truncate processing on the same Garnet endpoint.
- Full Cosmos destination upserts replace destination-only fields not emitted by
  the pipeline. Inline processing continues to PATCH existing source records.
- Chunk replacement is not atomic across batches/partitions. Insert-first can
  temporarily expose mixed revisions; delete-first can leave a search gap on
  failed insertion. Ordinary Cosmos chunk replacement does not add distributed
  revision fencing.
- Benchmark-only AKS GPU-count/zone pinning and the unvalidated DSE-Qwen2 OpenAI
  adapter are excluded.

## Known limitations and validation status

- Runtime API memory/storage-aware probe fixes and router scheduling recovery are
  not fully represented in default Helm configuration. API startup can still
  report healthy after store initialization fails. Operators must verify actual
  storage readiness and size resources for their workloads.
- Inline ingestion metrics omit model/source/destination attribution; model-filtered
  historical charts can omit Cosmos-inline and native-Garnet batches.
- Garnet endpoint normalization differs between API validation and the watcher;
  use identical endpoint representations for source and destination.
- The pipeline-worker OpenAI embeddings endpoint ignores encoding_format=base64
  and returns float lists. Use float responses or the negotiated binary protocol.
- Native Garnet watcher lease takeover, checkpoint failure, concurrent update, and
  deletion lifecycle coverage remains incomplete. OneLake and SharePoint still need
  release-specific live acceptance evidence.
- Release review: 1,183 Python unit tests passed and 3 failed (OpenAPI snapshot,
  PR image-build context expectation, and source-capability expectation).
  Playwright: 32 passed and 2 failed (missing Garnet source contract and a classic
  wizard timeout). These failures are not claimed as resolved.
- Connector regressions passed, including SharePoint, Cosmos source/chunk/inline,
  Blob polling, Garnet parser/revision, and bounded telemetry transport cases.
  Rust router: 17 passed. Go CLI tests passed.
